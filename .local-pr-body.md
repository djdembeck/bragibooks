## What

Cutover from Bragi-side catalog rematching and local path substitution to the m4b-merge engine's structured job protocol. The engine now owns metadata normalization, sanitization, tagging, chapter/artwork processing, and naming; Bragi captures an authoritative snapshot and consumes the engine's machine result.

Closes #479, #480.

## Why

- Worker-time catalog rematching re-resolved records under the engine's naming semantics, so the queued book could be named differently than the one the operator matched.
- Bragi's own path substitution evolved independently of the engine's resolver (sanitization, blank segments, extension handling), producing names the engine itself would not have produced.
- The legacy flow discovered outputs by scanning for the newest file, which is unsafe with concurrent jobs.

## How

**Durable versioned snapshot** — on Match save / metadata edit, the book's effective metadata is captured into a versioned `book_snapshots` row: ordered authors and narrators (capture order = output order, #479), canonical AudiobookDB book id (#480), release year, series, genres, title/subtitle, cover file reference, chapters. The snapshot plus the engine's schema/resolver identity is embedded in the queued job args, so a queued job is immutable: settings, profile, and re-match changes after enqueue cannot change it. Legacy books migrate on first capture; a missing book row is a hard error.

**Engine-backed preview and capabilities** — `GET /api/engine/capabilities` serves the engine's live capability document (schema, resolver, token vocabulary with examples); the Settings builder, profile validation, and Match's proposed output name all derive from it. `POST /api/engine/preview` runs the engine's non-mutating job preview over the exact payload a save records, so the name shown is the name the job will publish. No local token substitution remains.

**Structured worker invocation** — the worker hands the engine a `--job` file (`input_supplied` mode: Bragi never performs a worker-time catalog lookup) and consumes the `--machine` result. The engine's schema/resolver identity is verified at startup, before execution, and against the published result; a mismatch fails the job and preserves its staging for re-queue.

**Publication invariants** — every artifact path in the machine result is validated to lie inside the resolved output root (staging containment). The engine publishes via atomic no-replace links in its claim root; Bragi verifies the result and never discovers outputs by scanning. Cancellation terminates the m4b-merge subprocess group.

**Write policy** — a conditional all-supported policy: a field with a captured value is written from the snapshot, a blank field preserves the source tag (the engine rejects writes of blank values).

**Engine pin** — production and dev Docker images pin `m4b-merge` v2.2.0 by its immutable multi-arch index digest; the startup check verifies schema, resolver, and the supplied-mode `{book_id}` token via `--capabilities`, not just the version string. The minimum version floor is 2.2.0.

**Normalization** — a stored path format ending in a literal `.m4b` is stripped before the engine, which appends the extension itself; preview and execution normalize identically, so the displayed name always matches the published file.

## Post-review hardening (second commit)

An independent code review flagged three blockers and six follow-ups; all ten are addressed in `fix: harden engine job run gates and path validation`:

- Every run re-verifies the exact engine binary it launches before starting; saving a new engine binary runs the same gate before the save is accepted and refreshes the stored capabilities.
- Published-artifact containment is checked per path component, so a symlinked directory escaping the output root is rejected, not just a symlinked final file.
- Staging cleanup and the per-run staged cover are scoped to the running job (engine pid / job id); the output root is created before cover staging and the staged cover is removed after the run.
- Authorless snapshots send `authors: []` (the engine rejects `null`); a blank title uses `preserve`; a path token the engine does not know is rejected at save time, server and UI.
- Match's proposed name uses the same series normalization a save captures, so preview and stored snapshot cannot diverge.
- Cover downloads only follow public http(s) URLs (initial and every redirect hop), and preview errors no longer expose server temp paths.

## Second-review hardening (third commit)

The recheck found six further issues; all addressed in `fix(processing): resolve round-2 review findings`:

- The path-format token registry is published atomically, so a binary re-point cannot be read mid-replacement by a concurrent validation.
- A re-pointed binary's verified capabilities are retained from the pre-save gate and published together with the binary swap (no stale-registry window, no second probe).
- The Settings UI's unsupported-token check scans the serialized template, so a brace expression split across parts cannot bypass the server's E0 rule.
- Match's series re-parse trims with the server's Go whitespace set (U+0085 parity), so preview and capture cannot diverge.
- Cover fetches connect only to the validated public IP addresses (DNS-rebinding resistant); unspecified and 100.64.0.0/10 addresses are rejected.
- The per-run version probe runs under the run's context, so a cancelled run kills the probe's process tree.

Regression tests added for the concurrent registry (-race), the split-brace E0 case, U+0085 trimming, and the CGNAT/unspecified classifier. Re-verified against the real engine v2.2.0: preview and execution both resolve `575/Ada Lovelace, Second Author/Evidence Book.m4b`.

## Third-review hardening (fourth commit)

The second recheck left two P2 gaps, closed in `fix(processing): close binary/capability publication and cover redirect gaps`:

- A re-pointed binary's verified capabilities and token registry are published BEFORE the binary swap, so a concurrent reader can never pair the new binary with the previous binary's capabilities; a job captured under the old identity that runs on the new binary trips the identity check, fails closed, and recovers by re-queue.
- The cover fetch client no longer follows redirects internally (`ErrUseLastResponse`), so every 3xx reaches the per-hop loop that resolves, validates as public, and pins each destination to its own addresses.
- A single path-format validation now uses one registry snapshot end to end.

## Fourth-review hardening (fifth commit)

- A job's COMPLETE destination (output root, path format, completed directory) is frozen into the job row at enqueue time for every job — profile, override, and plain global alike — so a settings change after enqueue can no longer redirect or re-format a queued job; a row with no frozen destination fails with a clear re-queue message.
- The stored global path format AND every stored output-profile format are validated against the engine's token vocabulary at boot: a pre-existing legacy `{asin}` scheme fails startup with a nameable diagnosis instead of refusing jobs one by one.
- A book's processing snapshot degrades on catalog unavailability (retaining the previously captured genres/chapters/cover, refreshing the local fields); a hard capture failure invalidates the row and reports 500, so the book is refused at queue time, never run on stale data.
- Snapshot covers are written to capture-specific immutable filenames (`<bookID>-<nano>.jpg`) so a later capture can never overwrite, or remove on its own failure, the file an active queued job's snapshot references.
- The legacy `processor.Run` discovery-by-scanning path and its tests are removed; the structured `RunJob` path is the only execution route.

## Fifth-review hardening (sixth through eighth commits)

- Saving a global output path format applies the same relative-path rules as boot and enqueue (absolute path / `..` segment refused at save, not fatal at the next startup).
- Reprocess locates a run's inputs against the FROZEN completed directory recorded on that job (live-global fallback only for legacy rows), so a setting changed after the run no longer makes reprocess report the inputs missing.
- Cover pruning is per-file, book-scoped, and race-safe: it removes only the book's own snapshot-cover files that no live snapshot references (never source covers or other books' covers), skips the sweep entirely if the active-reference scan fails, and runs under a per-book lock that spans the capture's download + write + prune and the enqueue's snapshot read→insert, so the prune can never delete a file the paired job names.
- A hard snapshot-capture failure reports 500 and names the state, including when the invalidating delete itself fails.
- The cover fetch's DNS resolution is bound to the capture deadline.
- Independent review (full `develop...HEAD` diff) verdict: APPROVE, no open findings.
