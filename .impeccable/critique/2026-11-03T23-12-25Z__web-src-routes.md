## Overall Impression

The rebuild succeeds: triage is one move, navigation is header-only, and the empty/loading states are unusually disciplined. The biggest opportunity is making the state report and the action tell the same failure story — and making the book-detail recovery target findable.

## What's Working

1. **The single contextual CTA is the product's thesis made visible.** Urgency-ordered, count-carrying, and it names work rather than a destination. The old five-button row and its variant-shuffling ternaries are gone without losing a destination the header did not already own.
2. **Loading-state discipline is rare.** Three pre-settle states (announce-only window, skeleton, settled), sized placeholders, an invisible CTA reservation, `sr-only` announcements, and `libraryEmpty` gated on `hasLoaded && !error`.
3. **The Queue dedup is keyed to the exact inverse of the EmptyState condition**, so the gold action has one owner in every state. The book note is job-aware and matches the disabled button state.

## Priority Issues

**[P2] The report and the action disagree about failure.**
- **What:** 16 error books appear in the CTA but nowhere in the four-cell strip. The Queue cell instead says "Recent failed job," which describes job history (2 failed jobs), a different signal.
- **Why:** The page's stated job is to report state and offer one move. Here the report and the move tell two stories; a screen-reader user hears a stage summary and then an alarm. The user must reconcile book-errors vs failed-jobs unaided.
- **Fix:** Make the strip stage-only: remove the `queueError` "Recent failed job" branch so the gold CTA is the page's single failure statement. If the report itself should carry errors, add one non-interactive error line and drop the count from the CTA — but not both.
- **Suggested command:** `/impeccable clarify`

**[P2] The Compare note points to the weakest control, a section away.**
- **What:** "Choose Re-match in Actions…" refers to a ghost button beside a gold Re-process, in a panel above Compare on desktop and far above it on mobile. Compare is where the user learns the book is unmatched; the fix lives elsewhere.
- **Why:** The note is honest but sends the user hunting for the lowest-affordance element, across a section boundary, by its weakest trait.
- **Fix:** Raise Re-match from `ghost` to `secondary` in Actions so the named target is findable at a glance. Do not add a second Re-match in Compare — that recreates the duplicate this work removed.
- **Suggested command:** `/impeccable layout`

**[P3] The Import cell is a placeholder among live states.**
- **What:** "Import / Source folders" is the only cell answering "what is this?" while its siblings answer "what is the state?"
- **Why:** In a definition list labeled "Library pipeline," the mixed semantics read as unfinished and convey no readiness or configuration state.
- **Fix:** Reuse the settings fetch already made for the API notice and give Import a state: "Ready" when the input directory is configured, "Not configured" when it is not.
- **Suggested command:** `/impeccable clarify`

**[P3] Mobile straggler in the Queue empty state.**
- **What:** At 390px, "Match the remaining sources before adding them to a processing batch." wraps with "batch." alone at 14% of the measure.
- **Why:** It makes a calm empty state look untypeset at the exact width where the queue is most likely to be checked.
- **Fix:** Shorten to "Match the remaining sources before processing them." (or equivalent) so the last line carries a phrase, not an orphan.
- **Suggested command:** `/impeccable clarify`

## Persona Red Flags

**Alex (Power User):** The single CTA serializes triage. With 16 errors and 2 pending, only errors gets an on-page path; clearing them is one book at a time through catalog → book → Actions, with no bulk resolve or shortcuts. The header, now the designated secondary, has no count badges, so queue state is invisible from every other route.

**Jordan (First-Timer):** The pipeline strip and the Recent books cards share the same bordered-panel grammar, but one is inert. She will click "2 waiting" and nothing will happen. She also faces two failure terms on one screen with no indication whether they are the same problem.

**Sam (Accessibility):** The inert `<dl>`, `aria-live` loading branches, and text-explained in-flight lockout are solid. Red flags: the book note sends Sam to a disabled-ghost control in a section that may be far above at 200% zoom; "Recent failed job" announces a failure with no count, link, or landmark.

## Minor Observations

- The external-API notice still sits above the triage strip, delaying the state report on the page whose job is immediacy. Pre-existing, but more visible now.
- The CTA unmounts on fetch error and the space closes; acceptable in practice, but asymmetric.
- The in-flight book note says Re-match is unavailable but not where it will be once available. Half a sentence would close it.
- The dedup leaves the expanded pending disclosure without a local action when the EmptyState owns the move; the gold action is directly above. Accept this as the cost of single ownership — do not re-add the duplicate link.
- DESIGN.md's new rule names forbidden secondaries but does not resolve where book errors belong in the report; the P2 fix should update it.
- Mobile holds up well otherwise: 2×2 reading order, full-width CTA, ≥44px nav targets.

## Questions to Consider
